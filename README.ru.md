## ✨ Возможности

- ⚡ **Без установки** — Node.js нужен на системе, всё остальное на флешке
- 🔑 **Твой API-ключ** — хранится в `dsh-home/.credentials.yaml` на флешке
- 🧭 **Работает при любом пути/букве диска** — пути в лаунчерах относительно себя
- 🖥️ **Windows (`launch.cmd`) и Linux (`launch.sh`)** из одного бандла
- 🧩 **Работает на exFAT/FAT** — без симлинков, без прав доступа, без прав администратора
- 🔄 **Один dsh-home для обеих ОС** — сессии и настройки переезжают с тобой между системами
- 📦 **Только dsh, ничего личного** — в бандле нет ни сторонних плагинов, ни готовых пресетов агентов

## 🚀 Установка (без сборки)

**Что нужно:** флешка и [Node.js ≥ 18](https://nodejs.org), установленный на
компьютере, куда ты её вставляешь. Больше ничего — ни прав администратора, ни
установщика.

**1. Скачай бандл** со страницы
[**Releases**](https://github.com/Advokat-Babayki/DSH-Portable/releases/latest):

| Твоя ОС | Какой файл брать |
|---|---|
| Windows | `dsh-portable-windows-x64.zip` |
| Linux / macOS | `dsh-portable-linux-x64.tar.gz` |

**2. Распакуй на флешку** — в любую папку, на любую букву диска, например
`D:\dsh-portable\`:

```bash
# Linux / macOS
tar -xzf dsh-portable-linux-x64.tar.gz -C /media/usb/dsh-portable
```

*Windows:* возьми `.zip` и распакуй Проводником (правый клик →
**Извлечь всё**). Если скачал `.tar.gz` — Windows 10+ умеет распаковывать его
в PowerShell: `tar -xzf dsh-portable-linux-x64.tar.gz -C D:\dsh-portable`,
либо используй [7-Zip](https://7-zip.org).

**3. Запусти:**

```
Windows:        D:\dsh-portable\launch.cmd          (двойной клик)
Linux / macOS:  cd /media/usb/dsh-portable && ./launch.sh --profile web
```

**4. Добавь свой API-ключ** при первом запуске — `dsh-home/.credentials.yaml`:

```yaml
OPENROUTER_API_KEY: sk-or-v1-...
```

В систему не устанавливается ничего: сессии, настройки и ключи лежат в
`dsh-home/` на флешке, а `~/.dsh` не затрагивается. Одна и та же флешка
работает и на Windows, и на Linux — обе ОС используют общий `dsh-home/`.

> 🧩 **В бандле только сам dsh, и ничего личного** — ни сторонних плагинов, ни
> готовых пресетов агентов. Плагины кладутся в
> `dsh-home/profiles/<профиль>/`, пресеты агентов — в
> `dsh-home/.agent-presets/`: ставь свои, когда они понадобятся.

**Уже пользуешься dsh на этом компьютере?** Одна команда перенесёт твою
настройку на флешку — профили, настройки, сессии и (по желанию) API-ключи:

```bash
cd /media/usb/dsh-portable
bash init-portable.sh              # копирует и ключи; --no-creds — без них
```

## 🛠 Сборка из исходников

Собрать бандл самому из npm registry (нужны `node`, `npm`, `tar` и доступ в
сеть; примерно 15 минут и ~1 ГБ свободного места):

```bash
git clone https://github.com/Advokat-Babayki/DSH-Portable.git
cd DSH-Portable
bash make-portable.sh              # последняя версия @deepseek-ai/dsh
bash make-portable.sh 0.1.5-rc.1   # или конкретная версия (воспроизводимо)

# артефакты появятся в release/
#   dsh-portable-linux-x64.tar.gz  (собирается всегда)
#   dsh-portable-windows-x64.zip   (если в PATH есть `zip`)
```

Дальше распакуй архив на флешку точно так же, как в
[шаге 2](#-установка-без-сборки). Указывай версию явно: сборка «последней
версии» со временем устаревает.

## 🖥️ Запуск

**Linux:**

```bash
./launch.sh --profile web                # веб-интерфейс (обычно на :3080)
./launch.sh --profile headless "запрос"  # однократный запрос в консоли
./launch.sh --dump-config --profile web  # посмотреть конфигурацию
```

**Windows:**

```
X:\dsh-portable\launch.cmd
```

Оба лаунчера выставляют `DSH_HOME` на папку `dsh-home` рядом с собой и
`DSH_PORTABLE=true` (сигнал для пропатченного dsh — см.
[Как это работает](#-как-это-работает)).

| Что | Нужно |

| Запуск на Linux | `bash`, `tar` |

## 🔄 Обновление бандла

Твои данные — сессии, настройки, API-ключи — живут в `dsh-home/` и при замене
приложения **не затрагиваются**:

```bash
# 0. Осторожно: сделай резервную копию dsh-home/ (сессии, .credentials.yaml, settings.yaml)

# 1. Собери новый бандл (указывай версию явно — воспроизводимость)
bash make-portable.sh 0.1.5-rc.1

# 2. Распакуй во временную папку
tar -xzf release/dsh-portable-linux-x64.tar.gz -C /tmp/dsh-new

# 3. На флешке: оставь dsh-home, замени приложение и лаунчеры
rm -rf /media/usb/dsh-portable/dsh
cp -a /tmp/dsh-new/dsh /media/usb/dsh-portable/dsh
cp /tmp/dsh-new/launch.* /media/usb/dsh-portable/
```

Примечания:

- `make-portable.sh` полностью очищает `release/` перед каждой сборкой — не
  храни там ничего ценного.
- Настройки можно перенести в свежий бандл одним шагом:
  `bash make-portable.sh 0.1.5-rc.1 /path/to/.dsh`.
- Бандл собирается из версии npm, которую ты передал; сборка «последней версии»
  со временем устаревает — для воспроизводимости указывай версию явно.

## 💽 Выбор файловой системы флешки

| ФС | Симлинки | Права POSIX | Вердикт |
|---|:---:|:---:|---|
| **exFAT** | ❌ | ❌ | ✅ **Рекомендуется** — бандл спроектирован под неё; читается на Windows, Linux и macOS |
| **FAT32** | ❌ | ❌ | ⚠️ Работает, но лимит 4 ГБ на файл может мешать с длинными сессиями и кэшем |
| **NTFS** | через драйвер | эмулируются | ⚠️ Нормально для флешки «только для Windows»; на Linux (ntfs-3g) маппинг прав капризный |
| **ext4** | ✅ | ✅ | ✅ Лучший вариант «только для Linux»; Windows не читает его нативно |

Почему exFAT — выбор по умолчанию: на ней нет ни симлинков, ни битов прав, и
бандл именно под это пропатчен (см. ниже). Обратная сторона: любой, у кого есть
флешка, прочтёт любой файл на ней — включая `.credentials.yaml`
(см. [Безопасность](#-безопасность)).

## 📂 Что внутри

**Репозиторий** (то, что лежит в git) — это исходники обёртки, а не готовый бандл:

```
dsh-portable/
├── launch.sh            # лаунчер Linux
├── launch.cmd           # лаунчер Windows
├── make-portable.sh     # сборка бандла из npm → release/
├── init-portable.sh     # копирование ~/.dsh в dsh-home/
├── patch-js.mjs         # точные правки JS под exFAT (использует сборка)
├── README.md            # английская версия
├── README.ru.md         # ← ты здесь
├── CHANGELOG.md         # история релизов
└── LICENSE
```

**Собранный бандл** (`release/dsh-portable-linux-x64.tar.gz` или
`release/dsh-portable-windows-x64.zip`) — то, что распаковывается на флешку:

<details>
<summary>Нажми, чтобы развернуть структуру бандла</summary>

```
dsh-portable/
├── dsh/                     # @deepseek-ai/dsh и его зависимости (npm-пакет)
│   ├── lib/bin.js           # точка входа dsh
│   └── node_modules/        # плоские зависимости (пропатчены под exFAT)
├── dsh-home/                # DSH_HOME — все данные dsh
│   ├── settings.yaml        # настройки провайдеров и модели
│   ├── .credentials.yaml    # API-ключи
│   ├── profiles/            # профили (web, tui...)
│   │   └── node_modules/    # вторая копия дерева зависимостей (нужна без symlink)
│   ├── sessions/            # сессии
│   └── cache/ logs/ storages/
├── launch.sh                # Linux
├── launch.cmd               # Windows
├── README.md                # + README.ru.md
├── CHANGELOG.md
└── LICENSE
```

</details>

В репозитории `dsh/node_modules/` и `dsh-home/` намеренно отсутствуют
(см. `.gitignore`): это npm-дерево на сотни мегабайт, его всегда собирает
`make-portable.sh`. Поэтому **запускать `./launch.sh` из чистого чекаута
бессмысленно** — лаунчер скажет об этом и подскажет, что делать.

## ⚙️ Как это работает

```
launch.sh / launch.cmd
  ├─ DSH_HOME = <папка>/dsh-home    ← все данные остаются на флешке
  ├─ DSH_PORTABLE = true            ← сигнал для пропатченного dsh
  └─ node dsh/lib/bin.js "$@"       ← dsh читает $DSH_HOME и не трогает ~/.dsh
```

Без `DSH_HOME` dsh использует `~/.dsh` — но лаунчер переопределяет это.

Сборка применяет **три точечные правки** к дереву зависимостей
(`patch-js.mjs` — ровно одна замена на файл, иначе сборка падает):

<details>
<summary>Подробности патчей</summary>

| Файл | Что меняется | Зачем |
|---|---|---|
| `@deepseek-ai/dsh-app-boot` | `ensureSymlink`: реальный каталог вместо симлинка — это норма, а не ошибка | в бандле `node_modules` — настоящие каталоги; на exFAT симлинков нет |
| `@deepseek-ai/dsh-app-boot` | `symlinkSync`, упавший с `EPERM`/`ENOTSUP`/`EROFS`, не роняет старт | FAT/exFAT не умеют симлинки |
| `@deepseek-ai/dsh-credentials-local` | при `DSH_PORTABLE=true` проверка прав 0600 пропускается | FAT/exFAT не хранит права |

</details>

Патчи применяются к **обеим** копиям дерева (`dsh/node_modules` и
`dsh-home/profiles/node_modules`) и проверяются после сборки: наличие маркера
плюс `node --check` на распакованном архиве.

## 🔐 Безопасность

- `dsh-home/.credentials.yaml` — **обычный текстовый файл с API-ключами**, не
  шифруется. На флешке его прочитает любой, у кого есть доступ к носителю.
  `init-portable.sh` печатает об этом предупреждение и умеет не копировать
  ключи: `bash init-portable.sh --no-creds`.
- В git ключи не попадают: весь живой дом (`dsh-home/` — настройки, профили,
  сессии, `.credentials.yaml` и `.agent-presets/`) игнорируется, а своих
  пользовательских данных в репозитории нет вообще.
- Не коммить свой `dsh-home/`: это твои данные, а не исходники. `git add -A`
  на флешке безопасен — `.gitignore` закрывает всю папку.
- Права доступа: на FAT/exFAT файл всегда доступен всем, `chmod 600` там
  невозможен — поэтому в портативном режиме dsh не требует прав 0600
  (см. [Как это работает](#-как-это-работает)).

## 🛠 FAQ / Решение проблем

<details>
<summary><b>launch.sh пишет «не найден dsh/lib/bin.js»</b></summary>

Ты в чекауте исходников, а не в собранном бандле. Выполни `bash make-portable.sh`
и распакуй артефакт из `release/` на флешку — см.
[Сборка из исходников](#-сборка-из-исходников).

</details>

<details>
<summary><b>Windows не открывает скачанный файл</b></summary>

Бери артефакт под свою ОС: `-windows-x64.zip` для Windows,
`-linux-x64.tar.gz` для Linux/macOS. В каждом архиве лаунчер только своей ОС.
`.tar.gz` — не windows-формат; Windows 10+ всё же умеет распаковать его в
PowerShell (`tar -xzf dsh-portable-linux-x64.tar.gz -C D:\dsh-portable`) или
через [7-Zip](https://7-zip.org), но `launch.cmd` в нём нет.

</details>

<details>
<summary><b>Как добавить плагины или свои пресеты агентов?</b></summary>

Их в бандле нет — намеренно. `dsh-home/` начинается пустым и принадлежит тебе:
плагины кладутся в профиль `dsh-home/profiles/<профиль>/`, пресеты агентов — в
`dsh-home/.agent-presets/`, свои скиллы и настройки — туда же. Всё добавленное
остаётся на флешке, а `dsh-home/` игнорируется git, поэтому случайно в
репозиторий не утечёт.

</details>

<details>
<summary><b>Архив 80 МБ, а распакованная папка занимает куда больше</b></summary>

Для FAT/exFAT это нормально: эти ФС выделяют место кластерами, поэтому
~57 000 мелких файлов (дерево зависимостей, лежащее дважды) занимают несколько
гигабайт, хотя их реальный размер ~370 МБ. Флешки от 16 ГБ хватает с запасом;
NTFS/ext4 расходуют место экономнее, если твой сценарий это позволяет.

</details>

<details>
<summary><b>«node не найден в PATH»</b></summary>

Установи Node.js ≥ 18 (с [nodejs.org](https://nodejs.org) или из пакетного
менеджера). Бандл намеренно поставляется без Node.

</details>

<details>
<summary><b>tar при распаковке пишет «Cannot change ownership/permissions»</b></summary>

На FAT/exFAT это безвредно — эти ФС не хранят права POSIX. Файлы распаковываются
корректно.

</details>

<details>
<summary><b>Где живут мои сессии и настройки?</b></summary>

В `dsh-home/` рядом с лаунчером: `sessions/`, `settings.yaml`,
`.credentials.yaml`. Windows и Linux используют одну и ту же папку — сессии
переживают смену ОС.

</details>

<details>
<summary><b>Почему в бандле две копии node_modules? Это огромно.</b></summary>

Так задумано: Node ESM не поднимается из папки профиля в `dsh/node_modules`,
а симлинков на exFAT нет. Двойное дерево — цена за работу без прав администратора
и без правок ФС — см. [Ограничения](#-ограничения).

</details>

<details>
<summary><b>Сборка упала с «шаблон не найден» / «pattern not found»</b></summary>

Новая версия dsh изменила код, который ожидал патч, и сборка отказывается
молча собрать непатченный бандл. Зафиксируй предыдущую версию dsh
(`bash make-portable.sh 0.1.0-rc.7`) или дождись обновления DSH-Portable.

</details>

<details>
<summary><b>Пишет ли что-нибудь вне флешки?</b></summary>

Нет. `DSH_HOME` указывает внутрь `dsh-home/`, поэтому сессии, кэш и логи
остаются на флешке. `~/.dsh` и `~/.config` не затрагиваются.

</details>

## ⚠️ Ограничения

- **Размер**: дерево зависимостей лежит в бандле дважды (`dsh/node_modules` и
  `dsh-home/profiles/node_modules`), потому что Node ESM не поднимается из
  профиля в `dsh/node_modules`, а симлинков на exFAT нет. Это плата за работу
  без прав администратора и без правок ФС.
- **Windows-бандл** собирается на Linux: нативных аддонов в dsh нет, но
  платформенно-зависимые (native) зависимости в такой бандл не попадут —
  `npm install` идёт с `--no-optional --ignore-scripts`.
- dsh версии ≥ 0.1.5 меняет внутренний код `ensureSymlink`; сборка это
  учитывает, но при следующей смене шаблона упадёт с диагностикой, а не соберёт
  молча нерабочий бандл.
- На exFAT нет hardlink'ов: инструменты dsh, создающие файлы через
  `link(2)` (например, некоторые atomic-write пути), могут получить `EPERM`.
  Лаунчеры и сборка этого не делают; если упрёшься — используй ext4.
- **Без хардкода версии**: собранный из «последней версии» бандл со временем
  устаревает; для воспроизводимости указывай версию явно.

## 📝 История изменений

**1.0.0** — первый стабильный релиз. Сборка, лаунчеры и упаковка проверены на
реальной exFAT-флешке (сборка, распаковка, запуск). Главное:

- `make-portable.sh` действительно работает от начала до конца (раньше скрипт
  даже не разбирался синтаксически) и проверяет каждый применённый патч.
- Сделано под FAT/exFAT: без симлинков, без прав POSIX, без прав
  администратора — `npm install --no-bin-links` и три точечных патча дерева
  зависимостей.
- `launch.sh` / `launch.cmd` выставляют `DSH_HOME` и `DSH_PORTABLE`, проверяют
  Node.js и целостность бандла и объясняют, что делать, если чего-то не хватает.
- Репозиторий больше не носит в себе пользовательских данных: живой `dsh-home/`
  (настройки, профили, сессии, ключи, личные пресеты агентов) полностью
  игнорируется.
